## 二、案例介绍

### 标题
Buddy：双 AI Agent 协作编码平台 —— 让 AI 自主完成「实现 + 审查」闭环的提效实践

### 业务背景

使用单一 AI 编码助手普遍存在三类痛点：

1. **「实现即结束」，缺乏审查闭环**：单 Agent 一次性产出代码，质量全靠人工 Code Review 兜底，缺陷与返工在人工环节才暴露，成本高。
2. **长任务易跑偏、上下文易丢失**：复杂任务一轮跑不完，Agent 容易偏离目标或陷入重复错误，缺少机制性收敛。
3. **多 AI 工具割裂**：Claude、Codex、OpenCode、Kimi 各自为政，无法组合优势（如用 A 模型实现、B 模型审查），切换与管理成本高。

Buddy 面向上述场景，把「AI 编码」从单点辅助升级为**产品化、程序化的双 Agent 协作工作流**。

### 如何利用 AI 完成提效

Buddy 是一个 macOS 桌面应用（Electron 33 + TypeScript 5），核心机制是 **双 AI Actor 协作循环**：

- **执行方（Implementer）**：负责实现代码、修复问题；
- **审查方（Reviewer）**：检查执行方产出，提出修正或确认通过；
- 两者**轮流驱动同一任务**，每轮结束后进入可配置的人工校准窗口（COUNTDOWN），逐步收敛；
- 采用 **Dual-break 双确认机制**：必须双方都发出 `type=break` 才结束任务，单方无法终止，避免「单方误判完成」导致任务半途而废。

### 产品化、程序化工作流的具体落地

| 维度 | 实现 |
|------|------|
| **统一编排 4 种 AI** | 一套协议适配 Claude Code / Codex / OpenCode / Kimi，原生 CLI（`--resume` / `exec resume` / `--session`）与契约模式（`BUDDY_ACTOR` / `BUDDY_MODE` 环境变量）双通道，自由组合「实现+审查」的模型搭配 |
| **状态机驱动** | `READY → RUNNING_{ACTOR} → COUNTDOWN → (READY | PAUSED | DONE)`，可恢复、可暂停、可失败重试；崩溃重启后 `RUNNING_*` 任务自动重置为 `PAUSED`，从磁盘完整恢复 |
| **指令队列（InstructionQueue）** | Actor 运行期间可排队发送指令，轮次结束后自动执行，做到「人不在场也能持续干活」 |
| **上下文压缩与会话续跑** | 自动检测上下文超限（中英文错误均覆盖）并触发会话重置 + LLM 摘要压缩重试（`max_compact_retries` 可配）；Session 复用让长任务跨轮次延续，不丢上下文 |
| **Git 集成** | 本地化 conventional commit 消息生成、变更查看、提交与推送，AI 产出直接落到代码库 |
| **可观测 + 安全** | 事件流（`events.jsonl`）、对话记录（`transcript.jsonl`）全程留痕；API key 自动脱敏（`redact.ts`）；JSON 原子写入（`.tmp`→`rename`），Zod 读取时校验，保证数据一致性与前向兼容 |

## 三、实际提效数据（50 天真实运行数据）

> 以下数据由 `scripts/buddy-stats.mjs` 从本地 buddy 数据目录的实际任务记录（`state.json` / `events.jsonl`）统计得出。

| 指标 | 数值 | 说明 |
|------|------|------|
| 累计任务数 | **389** | 跨 21 个工作区（项目） |
| 任务完成率 | **93.6%** | DONE 364 / 389，失败仅 19 |
| 累计协作轮次 | **4196** | 双 Actor 交替执行的总轮次 |
| 单任务平均收敛轮次 | **10.8 轮** | 实现↔审查循环平均 10.8 轮达成双确认 |
| 单任务平均端到端时长 | **217 分钟** | 含人工校准窗口，实际人工值守时间远小于此 |
| 上下文压缩重置 | **21 次** | 长任务自动续跑，无需人工干预 |
| 日均任务吞吐 | **11.8** | 33 个活跃日 / 389 任务 |
| 参与 AI Actor | **4 种全覆盖** | claude 173、opencode 120、codex 84、kimi 13 |

**关键收益解读**：

1. **增效（高完成率 + 高吞吐）**：50 天内自主完成 364 个任务，完成率 93.6%，日均 11.8 个任务在双 Agent 协作下闭环。审查环节前置到 AI 之间，人工从「审全量代码」降级为「校准关键决策」。
2. **降本（无人值守长任务）**：单任务平均 217 分钟的端到端时长中，绝大部分由 AI 自主推进（含 21 次上下文自动压缩续跑），工程师无需全程盯守，可并行驾驭多个任务。按 364 个任务估算，相当于释放数百小时的纯人工编码 + Review 工时，释放出的人力投入到**新业务需求设计与架构优化**等高价值工作中。
3. **提质（机制化收敛）**：平均 10.8 轮实现↔审查循环 + 双确认机制，从机制上杜绝「单方草率收尾」，失败率仅 4.9%（19/389）。
4. **可复用（多模型编排验证）**：4 种 AI Actor 在同一套工作流下被真实调用并组合，证明跨模型、跨场景的可复用性——可按质量/成本/速度灵活搭配。

## 四、跨团队推广与复用价值

- **零后端依赖**：纯本地文件系统持久化（无数据库），数据目录与 Python 前代版本兼容，团队内开箱即用、低部署成本。
- **协议开放**：契约模式支持任意遵循 `BUDDY_*` 环境变量约定的命令接入，新模型/新工具可低成本纳入协作循环。
- **国际化与主题**：中简/中繁/英 + CJK 自动检测，23 套主题，适配多地区、多团队审美与语言习惯。
- **官网分发**：[http://buddy.intra.weibo.cn](http://buddy.intra.weibo.cn) 提供 DMG 下载与签名公证版本，便于跨团队标准化推广与版本统一。
- **数据可自证**：每个用户本地的 `scripts/buddy-stats.mjs` 即可跑出自己团队的真实提效数据，推广时有据可查。

## 五、灵魂拷问预演：为啥要造轮子？

### 一句话定调（开场先抢话术高地）

> 不是再造一个 Copilot/Claude Code，而是给这些单 Agent 工具补一个**协作编排层**。现有工具都是「单口相声」，Buddy 让它们演「多轮、多角色、可恢复、可审计」的戏。

### 核心：Buddy 解决的是「单 Agent 工具的结构性盲区」，不是功能重复

| # | 其他工具做不到 / 做不好 | Buddy 怎么补上 |
|---|------------------------|----------------|
| 1 | **AI 写完即结束，审查全靠人**：单 Agent 一次性产出，bug 与返工在人工 Review 才暴露 | 内建**双 Actor 实现↔审查循环**，平均 10.8 轮收敛后再交人，人工从「审全量代码」降级为「校准关键决策」 |
| 2 | **长任务一断就废**：人一走任务中断，上下文丢失，Agent 跑偏没人拽回来 | **状态机持久化 + 指令队列 + Session 续跑 + 上下文自动压缩**，发完指令可离场，崩溃重启可恢复 |
| 3 | **模型绑死**：每个工具只接自家模型，没法低成本做「A 实现 + B 审查」组合 | **统一协议编排 Claude/Codex/OpenCode/Kimi**，跨模型自由搭配，按质量/成本/速度权衡 |
| 4 | **黑盒不可复盘**：AI 改了一堆代码，事后说不清它经历了多少轮、为何如此 | 每任务留 `events.jsonl`/`transcript.jsonl`/`state.json` 全程留痕，**可观测、可审计** |

### 反问防御（被追问「那 Cursor/Claude Code 也能多轮啊」时）

> 对，它们能多轮对话，但那是**会话级**的多轮——断在终端里，不可恢复、不可编排、不可组合模型。Buddy 是**任务级**的多轮：有状态机、有持久化、有跨模型协议、有双确认收敛机制。这两者不在一个抽象层级上——就像「聊天记录」和「工作流引擎」的区别。

### 边界诚实声明（主动说，比被戳穿强）

> Buddy 不是万能的。它的**边界**很明确：
> - 它**不替代模型**——能力上限取决于背后接的 Claude/Codex 等；
> - 它**不替代人工**——双确认收敛的是「AI 之间的共识」，最终架构决策、业务正确性仍需人把关；
> - 它**最适用复杂、长周期、需要质量收敛**的任务；简单一次性改动用单 Agent 更轻。

### 数据可信度（最可能被质疑的点，提前堵）

> 「93.6% 完成率」会不会注水？——这是**本地真实任务记录**统计出来的，脚本 `scripts/buddy-stats.mjs` 开源可复跑，每个团队都能跑出自己的数据。完成率统计的是「任务状态机达到 DONE」，不代表「代码零缺陷」——但双确认机制意味着两个 AI 都认可该任务可收尾，比单方草率收尾可信得多。

### 收尾金句

> 别人卖的是「更聪明的嘴」，Buddy 卖的是「更靠谱的导演」——让现有 AI 工具按剧本演完整场戏，而不是各讲各的段子。

## 六、尖锐问题弹药库

### Q1：成本呢？跑 10.8 轮 × 389 任务，API 费用不吓人吗？

> **诚实拆账**：成本确实存在，但要算**净账**不是毛账。
> - 单任务平均 10.8 轮，但绝大多数轮次是增量修正，不是从头重写，token 消耗远低于「10.8 倍单次」。
> - 真正的对比基线是「**AI 轮次成本 vs 人工工时成本**」：一个任务若纯人工需 4 小时，AI 跑 10 轮的 token 费通常只有人工时薪的一小部分。
> - 而且 Buddy 支持**模型组合降本**：用便宜的开源模型做实现轮，强模型只做关键审查轮。这是单工具绑死模型做不到的成本杠杆。
> - 结论：成本可控、可调，且能用模型组合进一步压低。

### Q2：安全性？AI 自动改代码、自动 commit，出了事故谁负责？

> 三道闸：
> 1. **人工校准窗口（COUNTDOWN）**：每轮之间有人工介入点，不是全自动放飞；
> 2. **双确认才收尾**：两个独立 AI 都认可才 DONE，单方无法偷偷合入；
> 3. **Git 集成是本地化、可审的**：commit 前可看 diff，全过程 `transcript.jsonl` 留痕，事故可追溯。
> - 责任归属说清楚：**Buddy 不替代人的最终决策权**，commit 推送这类高危动作仍由人触发或确认。它是「放大器」不是「自动驾驶」。

### Q3：和 CI/CD 是什么关系？会冲突吗？

> **正交，不冲突**。Buddy 作用在「**写代码阶段**」——把需求变成可提交的代码；CI/CD 作用在「**集成阶段**」——验证已提交的代码。Buddy 产出的代码照常走 CI。甚至可以串联：Buddy 双确认 DONE → 自动建 PR → CI 跑测试 → 人合并。两者是流水线上下游，不是替代关系。

### Q4：团队推广的落地阻力？大家凭什么愿意换工具？

> 别一上来就推「全员替换」，按**三步走**降低阻力：
> 1. **先做增量试点**：挑一两个复杂任务用 Buddy 跑，拿真实数据（每个团队本地 `buddy-stats.mjs` 可跑出自己数据）说话，比 PPT 有力；
> 2. **零部署成本**是关键卖点——纯本地、无后端、装 DMG 即用，不增加运维负担，不碰公司基建；
> 3. **协议开放**：不绑死任何模型/工具，团队现有 Claude Code/Codex 直接接入，是「增强」不是「替换」，迁移心理成本低。

### Q5：10.8 轮才收敛，是不是说明 AI 还不够聪明，绕路太多？

> 反过来想：**能收敛才是关键**。单 Agent 工具是「一轮交付，正确与否靠人兜底」，绕路成本全转嫁给人。Buddy 把绕路**显性化、可观测、可自动恢复**——你能看到它走了几轮、在哪卡住、何时压缩了上下文。10.8 轮不是「笨」，是「**质量收敛的代价被量化、被前置到 AI 之间**」，而不是藏到线上事故里。

### Q6：会不会让初级工程师变废、依赖 AI 不长进？

> 这是个真问题，但方向反了——**Buddy 反而是学习加速器**：
> - 全程 `transcript.jsonl` 留痕，初级工程师可以复盘「Reviewer 是怎么挑出 Implementer 毛病的」，等于**围观两个 AI 互审**，比看静态代码学到更多；
> - 人工校准窗口逼着人做关键决策，不是当甩手掌柜；
> - 真正让人废掉的是「一键生成、看不懂就合」，Buddy 的双确认 + 留痕机制恰恰在对抗这种黑盒。
